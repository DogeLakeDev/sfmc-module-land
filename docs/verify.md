# 测试与验证

[English](verify.en.md) · [文档目录](README.md)

自动化用于验证领域状态、持久化与故障恢复。真实 Minecraft 事件、服务器加载和 UI 行为需要另行进服核对。本页手动步骤是验收预期，**尚未在真实 BDS 执行**。

## 开发检查

在模块根目录使用 Node >=22.13.0、pnpm 10.8.0：

```sh
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run lint
pnpm run test
```

`build` 目前等同于类型检查，不输出独立行为包。测试使用 Node 内置 test runner、node:sqlite 和项目已有 TypeScript 依赖；SQLite 的实验性提示不等同于用例失败，以退出码与测试汇总为准。

当前自动化基线：**36 项通过，类型检查与 ESLint 通过**。其中真实 Repository、Codec 和领域服务参与测试，Minecraft、经济和其他平台接口由适配替换；重启以保留数据库/经济状态并重建模块与索引模拟。

| 测试文件 | 重点 |
| --- | --- |
| `test/land-regression.test.cjs` | 区块恢复与重占领、买卖/租赁事务、故障回滚与确认丢失、财务并发、删除并发、租约撤权重试、奖励恢复 |
| `test/events.test.mjs` | 权限/成员变更通知与提交结果对应 |
| `test/presence.test.mjs` | 相邻领地/区域切换、进入离开顺序、离线与重复观测 |
| `test/harness.cjs` | 内存 SQLite、平台适配、故障注入与重启装配，不是生产 Minecraft 环境 |

单文件排查可以执行 `node --test test/land-regression.test.cjs`。已有自动化故障注入应在测试环境运行，不要通过修改生产账本状态“制造测试”。

## 实服前置与记录

准备测试世界、两个普通账号甲/乙及一个持有 land.admin 的管理账号；保证经济与 activity-log 已加载。先备份，再使用可丢弃领地。甲乙均需有可控余额，以验证成功与余额不足两条路径。

默认占领价 50、放弃不退款、银行初始为零、维护费启用、税关闭、荒野不保护、ban_eject 关闭。验证应记录实际配置，不要假定正在使用默认值。

```text
日期 / 执行人：
BDS 完整版本：
SFMC / SDK 版本：
Land 版本 / Git 提交：
脚本模块版本 / 实验设置：
配置副本与备份位置：
用例 / 操作者 / 坐标和维度：
预期 / 实际 / 日志 / 通过或失败：
```

## 实服验收清单

以下每项当前状态均为 **待执行**。命令中的“家园、仓库、乙”应替换为测试服实际名称；未写前缀的子命令同样通过 `/c:land` 执行。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 加载 | 检查 ready 日志与 help；重启一次 | 无缺失服务/事件报错；领地与授权仍在 |
| 创建/查询 | 甲 create 家园；here、info、bank | 首区块、领主、默认区域正确；玩家扣 50，银行未自动充值 |
| 负坐标/维度 | 在 -1/-16/-17 边界与不同维度查询、占领 | 分别落入 -1/-1/-2 区块；同 X/Z 不串维度 |
| 访客保护 | 甲/乙分别破坏、放置、开门/容器、实体交互 | 甲允许，乙按默认无角色拒绝；逐类核对映射 |
| 区域边界 | 两角选点并 area_create；测试贴边与重叠、跨未占领区块 | 两端方块包含；贴边成功，重叠与越界失败 |
| 区域覆盖角色 | 建仅 container.open 角色，area_member 给乙 | 区域内只有对应角色权限，区域外回退领地关系，不合并建造权限 |
| 邀请与关系 | invite→accept；kick/ban confirm；unban confirm | 接受前无成员授权；移除后旧区域授权清理，封禁优先；解封不自动恢复原角色 |
| 角色变更 | role_grant/revoke；有引用角色用 replacement 删除 | 后续动作立即按新角色；引用迁移，不产生悬空角色 |
| 释放/删除 | 尝试释放区域使用块、最后块；银行有余额时删除 | 均拒绝；清空约束后才能删除 |
| 银行 | deposit、withdraw confirm；余额不足重试 | 成功时两账户金额正确，失败不创建额外业务权益；不盲目重复输入 |
| 转让 | transfer 家园 乙 confirm | 新领主为乙；甲成为管理员，银行与租约保留 |
| 维护费 | 银行充足/不足分别到期；补款再 upkeep_pay | 成功推进到期日；不足欠费，宽限后按配置冻结；不会自动删除领地 |
| 升级 | 满足下一等级的区块/成员门槛并备足银行，upgrade confirm | 等级/额度/费用正确；奖励与持久标记一致 |
| 区域租赁 | rent_publish→rent_take；rent_renew；rent_end confirm 或等待到期 | 银行收款、区域租客角色、挂牌状态一致；结束撤销租客模板覆盖 |
| 区域/领地销售 | sell_area 或 sell_land→buy confirm | 区域只授区域角色；整领地转让所有权并将挂牌置售出 |
| PvP/爆炸/生物 | 分别设置 Flag 测近战、投射物、爆炸、登记敌对生物 | 按兼容矩阵记录实际覆盖；爆炸方块过滤不等同实体免伤，生物为事后移除 |
| 管理绕过 | admin_bypass on/off，在他人领地操作 | 开启允许常规世界动作，关闭恢复拒绝；另测 PvP Flag 的先行限制 |
| 扫描事件 | A→B、同地不同 Area、退出登录 | 对订阅服务记录 left→entered；默认区域 areaId 为空，离线 left 一次 |
| 重启/恢复 | 保存后重启，核对 admin_diag/admin_tx，测试副本执行 admin_repair | 数据与索引一致，未完成交易按恢复范围处理；恢复计数不等于成功数 |

测试维护费/租约时可在测试配置中缩短周期，再重载模块；仍受配置的最小周期与调度间隔约束。不要通过向前调整生产系统时钟验收。

## 必须单独记录的缺口

活塞、液体、火焰蔓延、自动化和跨边界副作用不能因直接方块测试通过就标记为通过。若测试了它们，应记录为不支持或记录实际缺口；参见[兼容性](compatibility.md)。

完整 API 集成还需核对消费方清单权限、actorId 的来源、回调不可用时的行为、奖励去重与服务重载清理。事件消费者必须在启动后重新查询，不能依赖通知完整补发。

验收失败时保存日志、配置、操作者、维度坐标与余额/账本对照；先用最小场景复现，再判断是模块错误、平台版本差异还是文档已列出的边界。数据排查步骤见[恢复手册](data-and-recovery.md)。
