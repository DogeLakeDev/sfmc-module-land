# 数据模型、迁移与恢复

[English](data-and-recovery.en.md) · [文档目录](README.md)

所有持久化通过 SDK 数据库服务完成。以下是逻辑表名；物理数据库路径、表名前缀和备份方式由 SFMC 平台决定。本模块不维护另一份 JSON 文件作为业务数据源。

## 表与关系

所有表禁用软删除。除身份表的 `player_id` 外，主键为 `id`。业务复合唯一性使用独立字符串键，不是 SQL 外键约束。

| 表 | 主要内容 | 唯一键或主要关联 |
| --- | --- | --- |
| `land2_land` | 名称、领主、状态、等级、描述、传送点、财务时间、元数据 | `name_key` 全局唯一；`owner_id` 索引 |
| `land2_claim` | 维度与区块 X/Z 的占领记录 | `claim_key` 唯一；`land_id` 索引 |
| `land2_area` | 默认区域或带维度的普通 AABB 区域 | `area_key = landId\|nameKey` 唯一 |
| `land2_role` | 稳定角色 ID、名称、权限 ID 数组、模板键、保留标记 | `role_key = landId\|nameKey` 唯一 |
| `land2_member` | 玩家关系与领地角色 | `member_key = landId\|playerId` 唯一 |
| `land2_area_role` | 某玩家在某区域的角色覆盖 | `assign_key = areaId\|playerId` 唯一 |
| `land2_flag` | 领地或区域的 Flag 值 | `flag_key = scope\|scopeId\|flagId` 唯一 |
| `land2_tx` | 动账模式、金额、来源/目标、业务载荷、状态、错误、经济交易 ID | `idempotency_key` 唯一；状态、领地、创建时间有索引 |
| `land2_lease` | 租客、区域、金额、租期、起止时间与状态 | 区域、领地、租客、到期时间、状态有索引 |
| `land2_listing` | 区域/领地挂牌、销售/出租类型、价格、发布者与状态 | 目标、领地、状态有索引 |
| `land2_registry` | 扩展定义、订阅、语言等登记项 | `item_key = kind\|key` 唯一 |
| `land2_identity` | 已知玩家 ID、名称、规范化名称 | `player_id` 主键；名称有索引 |
| `land2_reward` | 已完成升级奖励的本地标记 | `reward_key = landId\|level\|rewardId` 唯一 |

权限数组、Flag 值、元数据与交易载荷等以 JSON 文本保存在相应单元格内。领域服务负责验证跨表关系；数据库没有声明外键，也没有用唯一约束表达“每个区域只有一个有效租约”。核心写入队列与事务承担这些业务约束。

领地状态为 `active / delinquent / frozen`，租约为 `active / ended / expired`，挂牌为 `open / sold / closed`。普通区域引用领地；默认区域属于领地但没有普通 AABB。区域角色引用同一领地内的角色。详见[权限](permissions.md)与[区域](areas.md)。

## 资金与本地账本

领地银行账户 ID 是 `land:<landId>`。银行余额属于经济模块，不存储在 `land2_land`。本地交易支持 `none / debit / credit / transfer` 四种动账模式。

| 状态 | 含义 |
| --- | --- |
| `pending` | 已保存业务意图；经济调用可能未执行，也可能执行后尚未收到/保存结果 |
| `debited` | 经济步骤已确认，等待或正在应用本地业务 |
| `applied` | 本地业务完成；部分操作还需以当前世界状态检查是否仍适用 |
| `refunding` | 正在补偿经济步骤，可恢复重试 |
| `refunded` | 已完成补偿 |
| `failed` | 失败终态，不属于周期自动重放集合 |

正常路径是 `pending → debited → applied`；零金额也经过账本逻辑。可补偿失败进入退款流程。经济调用失败与业务已提交后的异常有不同处理，不能只凭异常文字判断应退款。

稳定基础键可以派生 `#` 修订号。恢复会校验操作者、账户、金额和模式；已成功记录也要核对业务状态，避免把过去已释放的占领当作本次新占领。经济模块必须持久地对幂等键去重，跨服务的一致性依赖这一契约。

### 当前保证与边界

- 买卖：转让/区域授权、挂牌售出、交易成功标记一起提交。整块领地转让保留银行与租约，原领主成为管理员；区域出售只授予区域成员角色。
- 租赁：租约、挂牌关闭、租客区域授权与成功标记一起提交。恢复可补齐旧版只创建租约的中间状态。
- 结束/到期：撤销仍属于租客模板的覆盖与变更租约状态一起提交；失败保留可重试状态。扫描还会检查旧版已结束但仍残留租客覆盖的记录；后续人为改成其他角色的授权不会被当成旧租客模板删除。
- 升级：等级已落库后不因奖励失败退款。奖励回调可能重复，接收模块必须按 `idempotencyKey` 持久去重。
- 存款/取款：手动请求的基础键含时间。崩溃后重新输入命令是新请求，可能再次动账，先核对银行和账本。
- 传送：收费完成后，实际 Minecraft 传送仍可能失败，当前没有该失败的自动退款。
- 事件：没有持久化事件发件箱；恢复不保证补发所有原始 after 通知，接收方应在启动时重新查询状态。

## 启动与自动恢复的时机

启动先定义表并加载索引、扩展与订阅，不会立即遍历全部未完成交易。周期调度默认每 6000 tick 依次尝试维护费/税费、租约到期和交易恢复；时间取决于服务器 tick 速度。

交易恢复处理 `pending / debited / refunding`，进入写入队列后重新读取记录，再按交易种类与持久载荷继续。恢复计数包含尝试和被捕获的失败，不能将其当成修复成功条数。日志与最终状态才是判断依据。

## 管理排查流程

先备份，在测试副本确认问题，再执行修复。以下命令需要 `land.admin`：

```text
/c:land admin_diag
/c:land admin_tx
/c:land admin_diag 家园
/c:land admin_repair 家园 confirm
/c:land admin_tx 家园
```

| 工具 | 实际范围 |
| --- | --- |
| `admin_diag [领地]` | 只读检查：默认区域、区域覆盖/重叠、成员角色引用、孤立区块等 |
| `tx [领地]`、`admin_tx [领地]` | 列出前 20 条非 applied 交易，也包含 failed/refunded；不是单笔查询或分页工具 |
| `admin_repair [领地] confirm` | 清理所选范围的孤立区块、补默认区域、尝试交易恢复；租约到期扫描仍是全局范围 |

诊断中的区域重叠检查目前没有过滤不同维度，可能报告跨维度假阳性；创建区域本身会区分维度。修复不会自动重划重叠区域、重建任意缺失角色、核对经济余额或强制修改账本状态。无参数 `admin_repair` 目前也能触发修复，不能依赖它实现强制二次确认。以上工具要求索引就绪；初始化失败需先处理平台/数据库错误。

不要为了消除告警而直接把交易改成 `applied` 或删除账本行。核对载荷、经济交易记录、实际归属、租约和授权后，才能确定后续恢复方式。当前没有公开“强制完成/退款某笔交易”接口。

## 迁移

不会读取、改写或自动导入旧 0.2 的 `sfmc_lands`。旧租赁不能直接解释为新所有权；如需历史数据迁移，应另做有映射规则、备份和核对报告的迁移工具。此仓库没有提供该工具。

已有 `land2_role` 缺少 `preset` 时，SDK 表定义负责补列；解码依次使用已保存模板键、未改名的模板显示名，最后仅在保留角色的权限集合唯一匹配某模板时推断。名称与权限都已修改的保留角色可能无法识别，转让或租赁会报 `role_not_found`。确认原语义并备份后，才可由数据库维护流程补回 `admin/member/visitor/tenant` 模板键。

`manifest.schemaVersion: 2` 是清单格式版本，不是业务数据库迁移编号。本模块没有独立的数据库版本表或完整迁移日志。

## 删除与备份

删除前要求银行余额为零，且没有有效租约、开放挂牌或未完成交易。删除会硬删除领地、区块、区域、角色、关系、区域授权、Flag、租约和挂牌；交易、奖励、扩展与身份记录保留。不会因此删除经济模块账户。

备份应在暂停写入或停服后统一保存 SFMC 数据库、模块配置、BDS 世界以及经济模块的权威数据（实际余额可能由其后端存储）。不要只恢复 Land 表而保留更新后的经济数据，否则已动账与本地业务可能分属不同时间点。恢复后在测试副本执行诊断、核对银行和玩家余额，再验证保护与租约，步骤见[测试与验证](verify.md)。
